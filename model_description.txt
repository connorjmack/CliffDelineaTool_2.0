================================================================================
CliffDelineaTool v2.0 - Deep Learning Model Architecture
================================================================================

This document provides a detailed technical description of the neural network
architecture used in CliffDelineaTool v2.0 for automated cliff base and top
detection from elevation transects.

================================================================================
OVERVIEW
================================================================================

Model Type: Hybrid 1D-CNN + BiLSTM + Multi-Head Attention
Task: Multi-task learning (segmentation + regression + confidence)
Input: 1D elevation transects with 13 engineered features per point
Output: Cliff base position, cliff top position, and confidence scores

Architecture Components:
1. 1D Convolutional Neural Network (CNN) - Local feature extraction
2. Bidirectional LSTM (BiLSTM) - Sequence encoding and context
3. Multi-Head Self-Attention - Focus mechanism
4. Multi-Task Output Heads - Segmentation, regression, and confidence

================================================================================
INPUT FEATURES (13 dimensions per point)
================================================================================

Location: v2/cliff_dl/data/preprocessing.py:202-216

Each point along a transect is represented by 13 normalized features:

GEOMETRIC FEATURES (Features 0-3):
-----------------------------------
0. elevation_normalized
   - Min-max normalized elevation [0, 1]
   - Raw DEM elevation scaled to unit range
   - Allows network to learn elevation patterns

1. distance_normalized
   - Distance from sea normalized to [0, 1]
   - Represents position along transect
   - 0 = seaward end, 1 = landward end

2. elevation_gradient
   - First derivative of elevation (dz/dx)
   - Normalized by standard deviation
   - Captures local slope magnitude and direction

3. elevation_curvature
   - Second derivative of elevation (d²z/dx²)
   - Normalized by standard deviation
   - Captures rate of slope change (convex vs concave)

DOMAIN FEATURES FROM v1.0 (Features 4-9):
-----------------------------------------
4. seaward_slope
   - Average slope angle to 20 points seaward (degrees/90)
   - Matches v1.0 implementation
   - Normalized to [0, 1]

5. landward_slope
   - Average slope angle to 20 points landward (degrees/90)
   - Matches v1.0 implementation
   - Normalized to [0, 1]

6. trendline_deviation
   - Elevation minus linear baseline (normalized by elevation range)
   - Positive = above trendline, negative = below
   - Captures deviations from overall transect trend

7. slope_change
   - Difference between landward and seaward slopes (normalized)
   - landward_slope - seaward_slope
   - Range: [-1, 1]
   - Positive at cliff base (seaward flat, landward steep)
   - Negative at cliff top (seaward steep, landward flat)

8. convexity_index
   - Signed curvature: curvature / (1 + gradient²)^(3/2)
   - Positive = convex (outward bulge)
   - Negative = concave (inward curve)

9. relative_elevation
   - Standardized elevation: (elevation - mean) / std
   - Z-score normalization
   - Captures position relative to transect average

ADDITIONAL GEOMORPHOLOGICAL FEATURES (Features 10-12):
------------------------------------------------------
10. low_elevation_zone
    - Binary indicator: 1 if elevation < 15m, else 0
    - Cliff bases typically occur in low elevation zones
    - Provides domain knowledge hint

11. shore_proximity
    - Exponential decay from sea: exp(-5.0 * normalized_distance)
    - High weight near shore (≈1.0), low inland (≈0.0)
    - Decay factor of 5.0 means 95% weight lost at 60% inland
    - Emphasizes that cliff bases are typically near shore

12. max_local_slope
    - Maximum absolute gradient in ±2 point window (5 points total)
    - Min-max normalized to [0, 1]
    - Cliffs have locally steep slopes

Input Shape: [batch_size, sequence_length, 13]
Typical sequence_length: 89-653 points (1m spacing along transect)

================================================================================
STAGE 1: 1D-CNN FEATURE EXTRACTOR
================================================================================

Location: v2/cliff_dl/models/cnn_lstm.py:108-126

Purpose: Learn multi-scale local patterns along the transect

Architecture:
-------------
Conv1D Layer 1:
  - Input channels: 13 (features)
  - Output channels: 64
  - Kernel size: 5 (looks at ±2 points around each position)
  - Padding: 2 (same padding, preserves sequence length)
  - Followed by: BatchNorm1d + ReLU + Dropout(0.2)

Conv1D Layer 2:
  - Input channels: 64
  - Output channels: 128
  - Kernel size: 5
  - Padding: 2
  - Followed by: BatchNorm1d + ReLU + Dropout(0.2)

Conv1D Layer 3:
  - Input channels: 128
  - Output channels: 64
  - Kernel size: 3 (smaller kernel for refinement)
  - Padding: 1
  - Followed by: BatchNorm1d + ReLU

Output Shape: [batch_size, sequence_length, 64]

How 1D Convolution Works:
--------------------------
Unlike 2D convolution (for images), 1D convolution slides along a sequence:

- Kernel shape: [kernel_size, in_channels, out_channels]
- At each position i, the kernel looks at points [i-2, i-1, i, i+1, i+2]
  for kernel_size=5
- Computes weighted sum across the 5 positions and 13 input channels
- Produces 64 output features per position

Example at a single point:
  Input window: 5 consecutive points × 13 features = 65 values
  Kernel: 5 × 13 × 64 = 4,160 learned weights
  Output: 64 features (one per filter)

What the CNN Learns:
--------------------
Each of the 64 filters learns to detect different patterns:
- Filter 1 might detect: "steep slope preceded by flat" → cliff base signature
- Filter 2 might detect: "concave curvature with high elevation" → cliff top
- Filter 3 might detect: "gradually increasing slope" → cliff face
- etc.

Multi-Scale Processing:
- Layer 1 (kernel=5): ~5m local context
- Layer 2 (kernel=5): ~13m context (overlapping 5m windows)
- Layer 3 (kernel=3): Refinement at ~17m context
- Much more flexible than v1.0's fixed 20-point window

Comparison to v1.0:
-------------------
v1.0: Hand-coded features (seaward slope, landward slope, trendline)
      Fixed 20-point window, manually chosen

v2.0: CNN learns which local patterns matter
      Multi-scale (5m, 13m, 17m effective receptive field)
      64 learned feature detectors vs 4 hand-coded features

================================================================================
STAGE 2: BiLSTM SEQUENCE ENCODER
================================================================================

Location: v2/cliff_dl/models/cnn_lstm.py:128-138

Purpose: Capture sequential context and long-range dependencies

Architecture:
-------------
Bidirectional LSTM:
  - Input size: 64 (from CNN output)
  - Hidden size: 128
  - Num layers: 2
  - Bidirectional: True (forward + backward)
  - Dropout: 0.3 (between layers)

Output Shape: [batch_size, sequence_length, 256]
  (256 = 128 hidden × 2 directions)

How Bidirectional LSTM Works:
------------------------------
Forward LSTM (reads seaward → landward):
  - At position i, has seen all points from 0 to i
  - Encodes: "I've seen flat beach, then steep slope starting at 35m..."
  - Hidden state carries information about transect history

Backward LSTM (reads landward → seaward):
  - At position i, has seen all points from sequence_end to i
  - Encodes: "There's a plateau ahead at 90m, currently in steep section..."
  - Hidden state carries information about transect future

Concatenation:
  - Forward hidden: [128 dims] "what I've seen so far"
  - Backward hidden: [128 dims] "what's coming up"
  - Combined: [256 dims] "full context from both directions"

Why BiLSTM is Critical:
-----------------------
Cliff detection is inherently relational:
  - Cliff BASE: Must be seaward of the cliff top
  - Cliff TOP: Must be landward of the cliff base
  - FACE: Region between base and top with steep slope

The BiLSTM enables the model to reason:
  - "I'm at 40m. The base was at 35m (forward memory), and I know the
     top is around 55m (backward memory), so I'm in the cliff face region."
  - "This steep slope at 60m is probably NOT a cliff base because I already
     passed through the base-face-top sequence."

LSTM State Dynamics:
--------------------
Each LSTM cell maintains:
  - Cell state (c_t): Long-term memory
  - Hidden state (h_t): Short-term working memory

Gates (learned):
  - Forget gate: What to remove from memory
  - Input gate: What new information to store
  - Output gate: What to output to next layer

Example learned behavior:
  - At cliff base: Store "base found at X meters" in cell state
  - In cliff face: Remember base position, look for top
  - At cliff top: Output "top found at Y meters", reset for next cliff

Packed Sequences:
-----------------
To handle variable-length transects efficiently:
  - Transects padded to max_length in batch
  - Pack_padded_sequence removes padding before LSTM
  - LSTM only processes valid points (not padding)
  - Pad_packed_sequence restores to [batch, seq_len, 256]

================================================================================
STAGE 3: MULTI-HEAD SELF-ATTENTION
================================================================================

Location: v2/cliff_dl/models/cnn_lstm.py:11-71, 143-151

Purpose: Learn which parts of the transect to focus on

Architecture:
-------------
Projection to attention dimension:
  - Linear(256 → 256)

Multi-Head Attention:
  - Number of heads: 8
  - Dimension per head: 256 / 8 = 32
  - Total dimension: 256
  - Dropout: 0.1

Residual Connection + Layer Normalization:
  - output = LayerNorm(input + attention(input))

Output Shape: [batch_size, sequence_length, 256]

How Multi-Head Attention Works:
--------------------------------
For each point in the sequence, attention computes:

1. Query (Q): "What am I looking for?"
   - Linear projection: Q = x @ W_q
   - Shape: [batch, seq_len, 256]

2. Key (K): "What information do I have?"
   - Linear projection: K = x @ W_k
   - Shape: [batch, seq_len, 256]

3. Value (V): "What information should I pass forward?"
   - Linear projection: V = x @ W_v
   - Shape: [batch, seq_len, 256]

4. Attention Scores:
   - scores = (Q @ K^T) / sqrt(32)
   - Shape: [batch, seq_len, seq_len]
   - scores[i, j] = "how much should position i attend to position j?"

5. Attention Weights:
   - weights = softmax(scores, dim=-1)
   - Converts scores to probabilities (sum to 1.0 across positions)

6. Attention Output:
   - output = weights @ V
   - Weighted sum of values based on attention weights

Multi-Head (8 heads):
  - Each head learns different attention patterns
  - Head 1: Might attend to steep slopes
  - Head 2: Might attend to elevation peaks
  - Head 3: Might attend to curvature changes
  - Head 4-8: Other specialized patterns
  - Concatenate all heads: 8 × 32 = 256 dimensions

Example Attention Pattern:
---------------------------
Consider a point at the cliff base (distance = 35m):

Attention weights might look like:
  - 0.45 weight on itself (35m) - "I'm at a transition"
  - 0.30 weight on steep face region (40-50m) - "steep slope ahead"
  - 0.15 weight on cliff top (55m) - "looking for top boundary"
  - 0.10 weight on other positions - "general context"

This allows the model to reason:
  "I'm at a steep transition (high self-attention), there's a sustained
   steep slope ahead (attend to face), and it ends around 55m (attend to top).
   This is likely the cliff base."

Residual Connection:
--------------------
output = LayerNorm(x + attention(x))

- Preserves original BiLSTM features while adding attention refinement
- Prevents vanishing gradients in deep networks
- Allows gradient to flow directly through the skip connection

Benefits of Attention:
----------------------
1. Variable-length handling: Works on any sequence length
2. Global context: Each point can attend to ALL other points
3. Interpretability: Attention weights show what the model focuses on
4. Selective focus: Ignores irrelevant regions (flat beach, inland plateau)

Masking (for padded sequences):
--------------------------------
If mask[i] = False (padding), then:
  - Set attention scores to -inf before softmax
  - Results in attention weight = 0 (no contribution)
  - Ensures padding doesn't influence predictions

================================================================================
STAGE 4: MULTI-TASK OUTPUT HEADS
================================================================================

Purpose: Generate three types of predictions simultaneously

Multi-task learning benefits:
- Regularization: Tasks share features, reducing overfitting
- Complementary: Segmentation finds region, regression refines position
- Robustness: Multiple objectives prevent model from exploiting shortcuts

--------------------------------------------------------------------------------
HEAD 1: SEGMENTATION (Classification)
--------------------------------------------------------------------------------

Location: v2/cliff_dl/models/cnn_lstm.py:154-160

Architecture:
  Linear(256 → 128) + ReLU + Dropout(0.2)
  Linear(128 → 3)

Output Shape: [batch_size, sequence_length, 3]

Output Interpretation:
  - Channel 0: Background logit (beach, cliff face, inland)
  - Channel 1: Cliff base logit
  - Channel 2: Cliff top logit

Softmax applied during inference:
  probs = softmax(logits, dim=-1)
  probs[i, :] sums to 1.0 across the 3 classes

Example output for a transect:
  Point 0 (beach):         [0.98, 0.01, 0.01]  → background
  Point 35 (cliff base):   [0.05, 0.90, 0.05]  → base
  Point 40 (cliff face):   [0.95, 0.03, 0.02]  → background
  Point 55 (cliff top):    [0.05, 0.05, 0.90]  → top
  Point 70 (inland):       [0.97, 0.02, 0.01]  → background

Soft Labels (Training):
-----------------------
Location: v2/cliff_dl/data/preprocessing.py:256-302

Instead of hard 0/1 labels, use Gaussian distributions:

  base_label[i] = exp(-0.5 * ((distance[i] - base_true) / σ)²)
  top_label[i] = exp(-0.5 * ((distance[i] - top_true) / σ)²)
  background_label[i] = 1.0 - max(base_label[i], top_label[i])

Where σ (sigma) is adaptive:
  σ = max(2.0, avg_point_spacing × 2.0)

Benefits of soft labels:
  - Allows nearby points to have partial credit (not binary right/wrong)
  - Gradual learning: Model learns approximate region first, then refines
  - Robust to label noise: 1-2m labeling error doesn't destroy learning
  - Matches uncertainty: Ground truth has ~1-2m uncertainty anyway

Example (with σ=2.0m and base_true=35.0m):
  distance[i]  base_label[i]
  33.0m        0.61  (close, partial credit)
  34.0m        0.88  (very close)
  35.0m        1.00  (exact)
  36.0m        0.88  (very close)
  37.0m        0.61  (close)
  40.0m        0.01  (too far, essentially 0)

--------------------------------------------------------------------------------
HEAD 2: REGRESSION (Distance Offset Prediction)
--------------------------------------------------------------------------------

Location: v2/cliff_dl/models/cnn_lstm.py:162-168

Architecture:
  Linear(256 → 128) + ReLU + Dropout(0.2)
  Linear(128 → 2)

Output Shape: [batch_size, sequence_length, 2]

Output Interpretation:
  - Channel 0: Offset to cliff base (meters)
  - Channel 1: Offset to cliff top (meters)

Offset definition:
  base_offset[i] = base_distance_true - current_distance[i]
  top_offset[i] = top_distance_true - current_distance[i]

Example for transect with base=35m, top=55m:
  Point i=0 (dist=0m):
    base_offset = 35 - 0 = +35m  (base is 35m landward)
    top_offset = 55 - 0 = +55m   (top is 55m landward)

  Point i=35 (dist=35m, at base):
    base_offset = 35 - 35 = 0m   (you are here!)
    top_offset = 55 - 35 = +20m  (top is 20m landward)

  Point i=55 (dist=55m, at top):
    base_offset = 35 - 55 = -20m (base is 20m seaward)
    top_offset = 55 - 55 = 0m    (you are here!)

Why Regression Helps:
  - Segmentation gives coarse region: "base is around here"
  - Regression refines: "exactly 0.5m landward from here"
  - Works even if segmentation is uncertain
  - Provides sub-meter precision

Combined Prediction:
  - Segmentation argmax: Find approximate location
  - Regression at that location: Fine-tune exact position
  - Final prediction = distances[argmax_idx] + regression[argmax_idx]

  (Note: Current implementation uses only segmentation argmax for simplicity,
   but regression head improves shared features via multi-task learning)

--------------------------------------------------------------------------------
HEAD 3: CONFIDENCE (Has-Cliff Classification)
--------------------------------------------------------------------------------

Location: v2/cliff_dl/models/cnn_lstm.py:170-177

Architecture:
  Max pooling across sequence: [batch, 256, seq_len] → [batch, 256]
  Linear(256 → 128) + ReLU + Dropout(0.2)
  Linear(128 → 1) + Sigmoid

Output Shape: [batch_size, 1]
Output Range: [0.0, 1.0] probability

Purpose: Transect-level binary classification
  - 1.0 = Confident this transect has a cliff
  - 0.0 = Confident this transect has NO cliff

Max pooling strategy:
  - Takes max activation across all positions in sequence
  - Captures strongest cliff signal anywhere in transect
  - If ANY point looks like a cliff, max pool will capture it

Example use cases:
  - Transect crosses only beach → confidence = 0.15 → reject
  - Transect crosses clear cliff → confidence = 0.92 → accept
  - Transect has ambiguous features → confidence = 0.55 → flag for review

Confidence threshold (default = 0.5):
  if confidence < 0.5:
      return "no cliff detected"
  else:
      return base and top predictions

Benefits:
  - Prevents false positives on cliff-less transects
  - Provides uncertainty quantification
  - Enables human-in-the-loop: "review low-confidence predictions"

================================================================================
PREDICTION PROCESS (INFERENCE)
================================================================================

Location: v2/cliff_dl/models/cnn_lstm.py:265-354

Step-by-step process for predicting cliff positions:

1. FORWARD PASS
   inputs: [batch, seq_len, 13] features
   outputs:
     - segmentation: [batch, seq_len, 3] logits
     - regression: [batch, seq_len, 2] offsets
     - confidence: [batch, 1] probability

2. APPLY SOFTMAX TO SEGMENTATION
   seg_probs = softmax(segmentation, dim=-1)
   Now seg_probs[i, :, k] are probabilities summing to 1.0

3. CHECK CONFIDENCE
   for each transect i:
       if confidence[i] < 0.5:
           base[i] = -1 (no cliff)
           top[i] = -1 (no cliff)
           continue

4. EXTRACT CLASS PROBABILITIES
   base_probs = seg_probs[:, :, 1]  # [batch, seq_len]
   top_probs = seg_probs[:, :, 2]   # [batch, seq_len]

5. FIND ARGMAX (Most Likely Positions)
   base_idx = argmax(base_probs[i, :])
   top_idx = argmax(top_probs[i, :])

6. VALIDATE GEOMETRIC CONSTRAINTS
   base_distance = distances[i, base_idx]
   top_distance = distances[i, top_idx]

   if top_distance > base_distance:
       # Valid: top is landward of base
       accept prediction
   else:
       # Invalid: reject
       base[i] = -1
       top[i] = -1

7. CHECK MINIMUM CONFIDENCE
   if base_probs[i, base_idx] < 0.1 or top_probs[i, top_idx] < 0.1:
       # Too uncertain, reject
       base[i] = -1
       top[i] = -1

8. RETURN RESULTS
   return {
       'base_distances': [batch],
       'top_distances': [batch],
       'base_confidences': [batch],
       'top_confidences': [batch],
       'has_cliff': [batch] boolean
   }

Example for a single transect:
  Segmentation outputs:
    Point 33m: base_prob=0.25, top_prob=0.05
    Point 35m: base_prob=0.85, top_prob=0.08  ← argmax for base
    Point 37m: base_prob=0.30, top_prob=0.10
    ...
    Point 53m: base_prob=0.05, top_prob=0.30
    Point 55m: base_prob=0.08, top_prob=0.78  ← argmax for top
    Point 57m: base_prob=0.05, top_prob=0.25

  Prediction:
    base_idx = 35m (highest base_prob = 0.85)
    top_idx = 55m (highest top_prob = 0.78)

  Validation:
    ✓ 55m > 35m (top landward of base)
    ✓ 0.85 > 0.1 (base confidence sufficient)
    ✓ 0.78 > 0.1 (top confidence sufficient)
    ✓ confidence = 0.92 > 0.5 (transect has cliff)

  Final output:
    base_distance = 35.0m
    top_distance = 55.0m
    base_confidence = 0.85
    top_confidence = 0.78
    has_cliff = True

================================================================================
LOSS FUNCTIONS (TRAINING)
================================================================================

Location: v2/cliff_dl/models/losses.py

Multi-task loss combines three components:

1. SEGMENTATION LOSS (Classification)
   - Cross-entropy between predicted probs and soft labels
   - Loss = -Σ (soft_label[k] × log(pred_prob[k])) for k in [0,1,2]
   - Penalizes wrong class predictions

2. REGRESSION LOSS (Distance Prediction)
   - Smooth L1 loss (Huber loss) on distance offsets
   - Loss = smooth_L1(predicted_offset - true_offset)
   - Robust to outliers (combines L1 and L2)

3. CONFIDENCE LOSS (Binary Classification)
   - Binary cross-entropy
   - Loss = -[y×log(p) + (1-y)×log(1-p)]
   - Where y=1 if transect has cliff, y=0 otherwise

Combined Loss:
  total_loss = α×seg_loss + β×reg_loss + γ×conf_loss

Typical weights:
  α = 1.0 (segmentation is primary task)
  β = 0.5 (regression is auxiliary)
  γ = 0.3 (confidence is auxiliary)

MODEL PARAMETERS
================================================================================

Total Parameters: ~1,500,000 trainable weights

Breakdown:
  CNN layers:       ~150,000 parameters
  BiLSTM layers:    ~700,000 parameters (2 layers × bidirectional)
  Attention:        ~300,000 parameters (Q, K, V projections)
  Output heads:     ~350,000 parameters (3 heads)

Comparison:
  v1.0: 8 manual parameters per AOI (64 total for 8 AOIs)
  v2.0: 1.5 million learned parameters (0 manual tuning)

Memory usage:
  Training: ~4-8 GB GPU RAM (with batch_size=16)
  Inference: ~2 GB GPU RAM or CPU-compatible

================================================================================
TRAINING CONFIGURATION
================================================================================

Optimizer: Adam
  - Learning rate: 0.001
  - Beta1: 0.9, Beta2: 0.999
  - Weight decay: 1e-5 (L2 regularization)

Learning rate schedule: ReduceLROnPlateau
  - Monitors validation loss
  - Reduces LR by factor of 0.5 when loss plateaus
  - Patience: 10 epochs

Batch size: 16 transects
  - Variable length sequences padded to max in batch

Epochs: 100-200
  - Early stopping if validation loss doesn't improve for 20 epochs

Data augmentation: None currently
  - Could add: random elevation noise, horizontal flipping, etc.

Regularization techniques:
  - Dropout: 0.2 (CNN), 0.3 (LSTM), 0.1 (Attention), 0.2 (Heads)
  - Batch normalization: In CNN layers
  - Layer normalization: In attention
  - Weight decay: 1e-5
  - Early stopping: Prevents overfitting

================================================================================
WHY THE ARCHITECTURE WORKS
================================================================================

1. CNN LEARNS MULTI-SCALE PATTERNS
   - Not constrained to 20-point window
   - Learns 64 different pattern detectors
   - Captures both fine-grained (5m) and coarse (17m) features

2. BiLSTM PROVIDES GLOBAL CONTEXT
   - Sees full transect structure
   - Remembers "I passed the base 15m ago, now looking for top"
   - Enforces structural consistency: base → face → top

3. ATTENTION FOCUSES EFFORT
   - Ignores flat beach and inland plateau (90% of points)
   - Focuses on critical transitions (10% of points)
   - Learns "where to look" from data

4. SOFT LABELS ENABLE GRADUAL LEARNING
   - Doesn't require pixel-perfect labels
   - Model learns approximate region first, then refines
   - Robust to ±2m labeling uncertainty

5. MULTI-TASK LEARNING REGULARIZES
   - Segmentation + regression + confidence share features
   - Prevents overfitting to single task
   - Tasks reinforce each other

6. END-TO-END DIFFERENTIABLE
   - All parameters optimized jointly
   - No manual feature engineering required
   - Automatically discovers optimal representations

Based on validation results showing remaining challenges (especially AOI8
cliff tops with MAE=35.5m), potential enhancements:

1. Attention Visualization
   - Export attention weights per prediction
   - Identify what the model focuses on
   - Debug failures in AOI8

2. Uncertainty Quantification
   - Monte Carlo dropout for prediction intervals
   - Output: "cliff top = 55m ± 3m (95% CI)"
   - Flag low-confidence predictions for review

3. Physics-Based Constraints
   - Hard constraint: top_distance > base_distance
   - Soft constraint: (top - base) in [5m, 100m] range
   - Maximum cliff height check

4. 2D Convolution (Future)
   - Process full DEM patches instead of 1D transects
   - Capture alongshore continuity naturally
   - Better handle curved coastlines

5. Ensemble Models
   - Train 3-5 models with different random seeds
   - Average predictions → typically 2-5% improvement
   - Reduces outliers and increases robustness

6. Active Learning for Difficult Cases
   - Identify low-confidence predictions in AOI8
   - Request human labels for just these cases
   - Retrain with augmented dataset
